# Rainy 桌面版

[English](desktop.md) | 中文

Rainy 是面向 Windows x64 的轻量 AI 工作台，用于办公、科研和编程。界面是原生程序（Rust + GPUI，`native/`），文档预览嵌入系统自带的 WebView2；自 4.1 起 Host 也是 Rust 程序，Rainy 不再附带 Node.js。核心安装包包含 Windows Host。编辑器的编程工具、Windows PHP 和 Linux 运行环境底座是可选组件，用到时下载；Strata 本地大模型及其模型也在“设置 → 工具”中按需下载。智能体运行在 Host 中，内置 `read`、`write`、`edit`、`grep`、`glob`、所选平台的 Shell（`pwsh` 或 `bash`）、`task` 以及联网和浏览器工具，另加用户启用的 MCP 工具。项目可以在 Windows 原生环境、WSL2 发行版，或通过 SSH 连接的 x86_64 Linux 服务器上运行。

[中文安装与配置指南](desktop-setup.zh-CN.md)负责产品流程、配置参考和源码构建说明。[验收记录](validation.md)区分模拟服务与真实 API 调用，并记录尚未完成的验收项。[第三方说明](../THIRD_PARTY_NOTICES.md)介绍打包的依赖及其许可。

## 4.0 与 3.x 的不同

- 界面由 `RainyAgent.exe`（GPUI）直接绘制，不再有 Electron 和 Chromium；Host、执行环境、协议和用户数据不变，3.x 的设置、对话、密钥和项目原样沿用。
- 3.x 顶部的“文件”“编辑”“视图”菜单合并到标题栏的项目菜单和命令面板（F1 或 Ctrl+Shift+P）：本文中“文件 → …”“视图 → …”指的命令都可以在命令面板里按名字找到。
- PDF、Office、所见即所得 Markdown、项目地图和 AI 内置浏览器由嵌入的 WebView2 显示，网页代码与 3.x 相同。

## 4.1 的变化

- Host 在每个执行目标上都是 Rust 程序 `rainy-host`：Windows、WSL 和 SSH 服务器。Rainy 不再包含 Node.js；运行和调试你自己的 JavaScript、TypeScript 使用目标环境中已安装的 Node.js。对话、设置、密钥、项目和记忆的格式不变，3.x、4.0 和 4.1 可以互相读取。
- 编辑器的语言服务和格式化改用原生程序：Python 用 ty，JavaScript 和 TypeScript 用 TypeScript 7 的原生编译器（语言服务和格式化），Python 格式化用 Ruff，C/C++ 用已安装的 clangd 和 clang-format。
- [Strata 本地推理](#strata-local-inference)回到“设置 → 模型”。
- “设置 → Skills 与 MCP”中每个 MCP 服务器都列出它的工具，可逐个开关。

## 4.3 的变化

- 新的“设置 → 工具”页：Rainy 默认不带任何第三方工具，需要哪个就下载哪个，不用了随时卸载。
- Windows 上编辑器的编程工具改为两个可选组件：Python 工具（`ide-python`：Ruff、ty、debugpy，约 26 MB）和 JavaScript / TypeScript 工具（`ide-web`：TypeScript 7、js-debug，约 11 MB）。Linux 运行环境仍自带这些工具。
- [Strata 本地推理](#strata-local-inference)移到“设置 → 工具”，改为下载 Strata 官方最新版并跟随更新，按这台电脑推荐模型。Rainy 不再提供 Strata 0.1.39 运行时组件。

## 离线安装与恢复

[发行页面](https://github.com/RainyMarks/Rainy/releases)提供核心安装程序。每个版本的 `v<版本>-resources` 发行存放该版本的 PHP 组件和 Linux 运行环境分片。[1.0.0 资源存档](https://github.com/RainyMarks/Rainy/releases/tag/v1.0.0-resources)仍存放 Strata 归档、`environment/` WSL 安装介质和 `environment-components/` 运行环境归档。核心可直接在 Windows 原生启动，无需 WSL 或科学计算库。源码打包按[输入清单](../toolpacks/build-inputs.v1.json)把固定版本的输入恢复至 `release/offline-<版本>`。

Rainy 3.0 不再包含 CTF 工具目录。旧版本下载的工具留在原安装位置（安装目录的 `tools` 文件夹或 `%APPDATA%\RainyAgent\native-tools`），Rainy 不再更新、修复或启动它们；不再需要时可自行删除这些文件夹。卸载应用会保留 `runtime/` 及用户数据。

新安装默认使用 Windows，已有保存的 WSL 选择继续保留。运行环境设置列出已注册 WSL2 发行版，也可使用外置离线介质准备应用自有的 Ubuntu 26.04.1 环境。安装 WSL 系统组件必须明确操作，并按 Windows 要求请求管理员确认及重启。已有发行版及数据保留。原发行版丢失时打开恢复入口，不静默切换目标。干净 Windows 上的管理员确认和重启恢复仍是独立验收项。

## 可选组件

核心安装包不含编辑器的编程工具、Windows PHP、Linux 运行环境底座（`linux-runtime.tar.xz`）和 Ubuntu 离线开发软件包。签名的载体资源 `optional-modules.json` 固定每个组件的归档，应用在需要时从 GitHub 发行分片下载到 `%APPDATA%\RainyAgent\modules\<id>`。每个分片和组装后的归档都校验 SHA-256，中断的下载通过 HTTP Range 续传，取消后保留已下载的分片供下次使用。

“设置 → 工具”可下载和删除 Python 编程工具（`ide-python`，约 26 MB）、JavaScript / TypeScript 编程工具（`ide-web`，约 11 MB）和 PHP。Host 在每次需要时才查找这些工具，所以下载完立即可用，删除后会提示缺少：状态栏说明某种语言缺哪个下载并可点开“工具”页，格式化和调试给出同样的提示。PHP 用于 Windows 原生目标；“代码工作区”一节说明项目如何选择 PHP。Strata 不是这里的组件，见 [Strata 本地推理](#strata-local-inference)。

WSL 和 SSH 目标都使用 Linux 运行环境。Linux 运行环境分两层：底座（Linux 开发工具：Ruff、ty、TypeScript 原生编译器、debugpy 和 js-debug，下载约 27 MB，解开后约 90 MB）只在这些内容变化时才需要联网下载，启动页显示进度；应用层（`rainy-host`、预览页面和小资源，约 11 MB）随安装包附带。底座没变的更新直接换上新的应用层，不下载；第一次升级到分层版本时，内容相同的旧版运行环境会以硬链接复用为底座，也不下载。每个版本解包为 `~/.rainy-agent/runtime/<应用层摘要>/`，其中的开发工具是指向 `base-<内容摘要>/` 的链接。下载失败时，对话框提供“重试”“改用 Windows 原生运行”和“退出”。改用 Windows 原生运行会把 Windows 记录为执行目标，与在设置中切换相同。以 WSL 启动约一分钟后，已安装的应用会删除旧版本解压在 `~/.rainy-agent/runtime` 中的运行环境和不再使用的底座，保留本版本、它的底座以及仍有进程在使用的运行环境。服务器如何获得运行环境见 [SSH 远程开发](#ssh-remote-development)。

启动约 60 秒后，安装版会删除旧安装程序留在 `resources` 目录中的资源：`strata-runtime`、`php`、`linux-runtime.tar.gz`、`native-tools-metadata.json`、`native-tools-download.json`、`native-tools-catalog.json`、`native-tools-channel.signed.json` 和 `native-tools-public-keys.json`。

## 应用更新

安装版在启动时检查 GitHub `RainyMarks/Rainy` 的稳定发行版，并在有新版本时后台下载核心更新。“帮助 → 检查更新”提供手动状态查看与重试。准备完成后可选择“稍后”或“重启安装”；只有确认、草稿保存和 Host 清理完成后才启动安装。保存失败会保留应用窗口。普通退出不会安装已下载的更新，更新器不会选择预发布版或降级已安装版本。

自动更新替换核心应用并保留已安装的环境，不会重新下载 WSL 介质或 CPU/CUDA 环境组件；更新后首次以 WSL 或 SSH 启动时换上该版本的应用层，底座变化时才下载。CPU/CUDA 环境组件仍从匹配的离线发行文件导入。[验收记录](validation.md)按发布产物记录已经完成的更新检查。

## 资源管理器集成

两项默认都关闭，要在 **设置 → 通用设置 → 系统集成** 里自己打开；打开之前 Rainy 不写注册表。打开后，安装版把自己登记到当前用户的注册表（`HKCU\Software\Classes`），不需要管理员权限；从源码运行的开发版不登记。（3.9.0 会自动打开这两项；3.9.1 会删除 3.9.0 写入的登记，除非你重新打开。）

- **右键菜单**：文件、文件夹和文件夹空白处的“通过 Rainy 打开”（英文界面为“Open with Rainy”）。Windows 11 把这类菜单项放在“显示更多选项”里。
- **打开方式与默认应用**：80 种扩展名（Markdown、纯文本、JSON / YAML 等配置文件、常见编程语言、LaTeX 等）登记了 `Rainy.<扩展名>` 文件类型，Rainy 出现在它们的“打开方式”里，并登记为可以在 Windows“默认应用”中选择的应用。还没有默认应用的类型，由于 Windows 只认识 Rainy 这一个程序，可能直接用 Rainy 打开。Windows 不允许应用自己把自己设为默认；**设置 → 通用设置 → 系统集成 → 设为默认应用** 的“打开系统设置…”打开 Windows 的默认应用设置：Windows 已把 Rainy 列入应用列表时直接到 Rainy 的页面，刚登记、还没列出时停在默认应用首页，可在“为文件类型设置默认值”中输入 `.md` 等类型选择 Rainy。

关闭某一项时立即删除对应的注册表项：只删 Rainy 自己的键和值；上层的键只有在因此变空、并且打开这一项之前并不存在时才删（打开时 Rainy 会在 `desktop.json` 里记下哪些键原本就有），其他程序的登记和你原有的键都不受影响。切换界面语言后，菜单文字随之更新。卸载 Rainy 时删除全部登记，升级保留你的选择。

通过这些方式打开时，路径作为命令行参数传给 Rainy；Rainy 已经在运行时，新进程把路径交给已有窗口后退出。文件夹作为项目打开；文件在已登记且包含它的最深一层项目中打开，没有这样的项目时以文件所在的文件夹作为项目。执行环境为 WSL 时，路径映射为发行版中的路径；为 SSH 时不打开本机路径，并提示先切换执行环境。找不到的路径会列出来。

## 诊断信息

Rainy 在本机保存 WebView2 的崩溃记录，不会上传。“设置 → 通用 → 诊断信息 → 导出…”会把版本和系统信息、执行后端日志和 Strata 日志的末尾部分，以及最近 5 份崩溃记录打包成 zip，并在文件夹中显示。日志里的密钥、令牌、密码和 Windows 用户名会被隐去；设置、对话和 API 密钥不会被打包。报错、对话框和菜单跟随“设置 → 通用”中选择的界面语言。

## 运行时约定

Host（[架构说明](architecture.md)）不包含官方账号、遥测、办公运行库、浏览器与电脑操作、定时任务、多 Agent 工具和插件市场。一个选定的 Host 负责命令、终端、模型连接及会话，可位于 Windows 原生环境、WSL 发行版或通过 SSH 连接的 Linux 服务器；Windows 外壳负责窗口及共享项目目录。生命周期控制使用标准输入输出，应用数据使用认证后的 HTTP/WebSocket。切换执行目标前保存草稿，并拒绝运行中或排队中的 Agent 工作、程序、调试及终端；修改目标选择前冻结新执行，随后 Rainy 重启并进入新目标。状态栏显示当前目标，例如 `Windows`、`WSL · Ubuntu` 或 `SSH · 主机`。

WSL 和 SSH 启动在 Host 报告就绪后，还会等待 Windows 侧 loopback TCP 可达。连接拒绝会在原有 90 秒启动期限内重试，其他连接错误会使启动失败。该检查不发送 HTTP 请求或认证 token。取消、超时及 Host 退出都会停止探测，transport 关闭会等待所拥有的 socket 和子进程退出。Windows 原生启动不执行跨系统探测。

窗口立即显示启动页并报告每个准备步骤。窗口按上次关闭时保存的大小、位置和最大化状态重新打开；首次启动或保存位置所在的显示器已断开时，默认大小在主显示器居中，主显示器较小时最大化。之前启动已记录的 WSL 目标会跳过环境检查窗口：启动只用一次 WSL 调用映射载体路径并解包 Host，该目标不可用时才打开检查。每次启动都会把各阶段耗时追加到 `host.log`。

原生窗口控制与单行顶部工具栏共用区域。顶部空白处支持拖动和双击最大化，编辑和缩放快捷键仍可使用。统一设置分别提供模型、上下文、项目记忆、Skills、MCP 和运行环境。运行环境页可选择执行目标、检查已有解释器、导入发行包认可的离线组件及管理 SSH 主机。

新工作区显示左侧文件树和主编辑区，需要时通过顶栏按钮展开 AI 对话和底部面板；“视图 → 专注编辑”收起两者。已有工作区保留保存的面板开关与宽度。文件操作只有一行，编辑器操作与已开标签共用一行。空间不足时文件栏可覆盖编辑器显示。文件标签与对话分别保存状态。主页和“关于”署名为 `Developed by RainyMarks`。推理运行时英文显示“Thinking...”，中文显示“思考中”并带已用秒数，完成后显示“已思考 12s”；计时控件使用对应的本地化文字。回答输出时对话自动跟随；用滚轮、键盘或滚动条向上翻会立即停止跟随（平滑滚动途中也不会被拉回），点“查看最新输出”或滚回底部即恢复。输入法选字时按回车或 Esc 不会发送、重命名或取消。空白页面（未打开项目、未打开文件、新对话）飘着强调色的细雨，点击背景会泛起涟漪；“设置 → 外观 → 动效”可以关闭，Windows 开启“减少动态效果”时雨保持静止。Rainy 标志使用强调色，鼠标指向时三道雨线落下，当前对话运行时顶栏标志一直下雨。推理块显示雨云图标，模型思考时云下的雨滴依次落下。

## SSH 远程开发

SSH 执行目标让 Host（智能体、终端、运行与调试、语言服务和文件访问）在 x86_64 Linux 服务器上运行，界面仍留在这台电脑上。Rainy 使用 Windows 自带的 OpenSSH 客户端（`C:\Windows\System32\OpenSSH\ssh.exe`），因此 `~/.ssh/config`、密钥、ssh-agent 和 ProxyJump 与在终端中使用时一样有效。缺少该客户端时，在 Windows“设置 → 系统 → 可选功能”中添加“OpenSSH 客户端”。

服务器需要 x86_64 Linux、用于安装和启动后端的 `python3`，以及足以运行 Node 22 的 glibc。Rainy 不做任何系统级安装：运行环境放在 `~/.rainy-agent/runtime/<sha256>`，设置和对话保存在服务器的 `~/.rainy-agent` 中。

首次连接会安装本版本的 Linux 运行环境（归档约 280 MB）。服务器先自行从 GitHub `v<版本>-resources` 发行分片下载并逐片校验，中断后可续传；下载失败，或一分钟后速度仍低于 256 KiB/s 时，改由这台电脑下载归档并通过 SSH 连接上传。每个归档都按签名发行包中固定的 SHA-256 校验。之后启动直接复用已安装的运行环境，测试中约 2 秒即进入工作台。旧版本的运行环境会在后台从服务器上删除。

Host 在服务器上只监听 127.0.0.1，ssh 把同一端口号转发到这台电脑的 127.0.0.1（`ssh -L`），因此不会在公网接口上监听。连接新服务器时，Rainy 用自己的对话框显示主机密钥指纹；信任的密钥写入 `~/.ssh/known_hosts`，密钥发生变化时拒绝连接并说明原因。密码、密钥口令和一次性验证码在 Rainy 的小窗口中输入，只在本次运行期间保存在内存中，不会写入磁盘。

“设置 → 运行环境 → SSH 远程开发”自动列出 `~/.ssh/config` 中的主机，以及在 Rainy 中添加的主机。“连接并添加”先测试一次连接（登录、Linux x86_64 和 `python3`），通过后再保存。“切换到此主机”更换执行目标；在 Rainy 中添加的主机可以移除。同一页的执行目标列表也会列出 SSH 主机，命令面板提供“连接到 SSH 主机…”。切换后 Rainy 会重启并进入新目标，与 WSL 相同。

使用 SSH 主机时：

- 用应用内的文件夹浏览器打开文件夹，不提供 Windows 文件夹选择框。从这台电脑拖入的文件不会映射为服务器路径。
- “准备离线组件”会提示在服务器上安装工具（apt、pip、nvm），再使用“检测已有环境”。
- 服务器访问不到这台电脑上的 Strata 本地模型，请配置服务器能访问的模型地址。模型请求从服务器的网络发出。
- 模型设置和 API 密钥按执行目标分别保存。API 密钥加密保存在服务器上，加密用的钥匙由这台电脑在每次运行时提供。
- 项目和项目记忆保存在服务器上；在这台电脑和服务器之间切换时，项目不会随之迁移。

连接断开时，Rainy 提示与 `SSH · 主机` 的连接已断开，并提供“重新连接”（重新打开 Rainy）；对话历史保存在服务器上。启动失败时可选择“重试”“改用 Windows 原生运行”或“退出”。

## 工作台

AI 窗格中是与智能体的对话。智能体在每个对话所选的权限模式下读写项目文件、运行命令（权限模式见“模型体验”）。被智能体修改的文件列在输入框上方；打开后可在编辑器中逐处查看改动，选择保留或撤销；开启“自动保留”后，发送下一条消息时会保留尚未处理的改动。编辑器提供 AI 行内补全和 Ctrl+K 改写选中代码。侧边栏包含文件树、跨文件搜索替换和 Git 面板，Git 面板可以用对话模型生成提交说明。项目地图展示项目的各个部分及其引用关系，命令面板可按名称执行命令。项目记忆、Skills（`.rainy/skills`）和 MCP 服务在设置中配置。设置里有 DeepSeek 模型的 API 密钥时，对话还有 `web_search`（DeepSeek Search 接口，`POST /v1/tools/search`）和 `web_fetch`（Fetch 接口，`POST /v1/tools/fetch`）两个工具，请求经 Host 发出并遵循网络代理设置；搜索不需要批准，读取网页在询问和只读模式下按网站询问一次，可在项目中记住为 `web_fetch:<网站>` 规则（设置 → 安全中可移除）。在 **设置 → 模型 → 联网搜索** 中可以关闭。“添加文件夹”挂载其他目录，每个根目录拥有稳定标识，跨根文件操作按该标识限定范围。Windows 项目使用原生路径；WSL 项目使用在所选发行版中映射并规范化的路径；SSH 项目使用服务器上的路径。已有工作区保留身份、编辑恢复和原执行目标中的聊天。在 Windows 与 WSL 之间切换项目时把公开项目身份绑定至新目标，恢复目录挂载，并在 Host 就绪前选中该工作区；旧聊天及编辑恢复仍留在原 Host。

编辑器提供多文件标签、按文件类型加载的语法高亮、查找替换、转到行、撤销、显式保存和内联差异视图。文件操作保留 UTF-8 BOM 和换行方式；混用两种换行的文件保存时统一为 LF。二进制、非 UTF-8 及超限文档只读，默认可编辑上限为 5 MiB。超限 UTF-8 文件最多预览 64 KiB，不截断字符。

编辑器不能编辑的文件会用查看器打开。图片可缩放、拖动、查看像素颜色，并可“添加到对话”。Markdown 默认以所见即所得方式打开（Milkdown Crepe），可切换到源码、预览和左右分栏；所见即所得的修改写入同一缓冲区，保存时按行与载入时的序列化结果合并，只有改动的行使用编辑器的写法。SVG 可在源码、预览和分栏之间切换（Ctrl+Shift+V、Ctrl+K V）；Markdown 预览跟随未保存的修改，并与编辑器同步滚动。PDF 按需渲染页面，可复制全部文字（包括隐藏文字）；未嵌入的 CJK 字体使用随附的 pdf.js 字符映射（`resources/pdfjs/cmaps`）和标准字体显示。Word（.docx）由页面自己排成分页纸面，也可切换为“用 Office 版式显示”；PPT（.pptx、.ppt）和旧版 Word（.doc）在桌面版中交给本机的 Microsoft Office 或 WPS 转成 PDF 显示（文件经 Host 读取，所以 WSL 和 SSH 上的文件同样可以），没有 Office 时列出每页幻灯片的文字；Excel（.xlsx、.xls、.ods）显示为表格，最多 2000 行、200 列。文档上方的“用默认程序打开”只接受文档类型，SSH 上的文件不提供。`~$` 开头的 Office 锁定文件显示是谁打开了哪个文档，`.lnk` 快捷方式显示目标路径、参数和起始位置。音频和视频用系统播放器播放。任何文件都可以用十六进制视图打开：任意大小的文件都能翻阅，支持跳转偏移（Ctrl+G）、数据检查器、多种复制格式和文件类型识别。GBK、UTF-16 等非 UTF-8 文本以只读方式显示，可选择编码。快速打开搜索工作区路径，限制结果数量，并提示截断。更改查询、切换项目或重新打开窗口会使旧结果失效；搜索等待或失败时不能打开旧结果。

Markdown 的所见即所得视图按 Typora 的习惯设计。侧栏“大纲”列出文档的标题，跟随阅读位置（源码视图中为光标所在行）高亮，点击即跳转。Ctrl+F / Ctrl+H 打开查找替换，匹配可以跨越加粗等格式，不进入代码块，可区分大小写；“全部替换”一步即可撤销。粘贴或拖入的图片（每张不超过 25 MB）经 Host 保存到文档旁的 `assets` 文件夹、“文档名.assets”文件夹或文档所在的文件夹（**设置 → 通用设置 → Markdown**），同名时加 `-1` 等后缀，文档中写入相对路径；剪贴板中的截图按时间命名。公式块和 Mermaid 图表失去焦点后只显示渲染结果，点击后显示源码和实时预览；Mermaid 按需加载，以 strict 安全级别渲染。YAML（`---`）或 TOML（`+++`）前言显示在顶部单独的文本框中。快捷键：Ctrl+0–6 正文和各级标题，Ctrl+= / Ctrl+- 调整标题级别，Ctrl+T 插入 3×3 表格，Ctrl+Shift+K 代码块，Ctrl+Shift+M 公式块，Ctrl+Shift+Q 引用，Ctrl+Shift+[ / ] 有序和无序列表，Alt+Shift+5 删除线，Ctrl+Shift+` 行内代码，Ctrl+K 链接，Ctrl+/ 切换源码；按住 Ctrl 单击链接时，网址和邮件地址交给系统打开，项目里的文件在编辑器中打开，`#标题` 跳到本文的标题。F8 专注模式淡化当前段落以外的内容，F9 打字机模式让光标所在行保持在视图中部。状态栏显示字数（中日韩文字按字计，其他文字按词计），悬停显示字符数和阅读时间。“文件 → 导出为 PDF… / 导出为 HTML…”生成自包含的页面：代码高亮、公式（MathML）、Mermaid 图表（SVG）和本地图片（data URL）都嵌入其中，前言不打印，网络图片保留原链接；PDF 在禁用脚本的隐藏窗口中按 A4 打印，带书签和无障碍标签；Chromium 的 ToUnicode 映射把与部首共用字形的汉字（如“二”“文”）记成康熙部首，导出时以增量更新改回 NFKC 对应的汉字，使复制和搜索得到原文（`native/crates/app/src/web/pdf_text.rs`，PDF 由隐藏的 WebView2 打印）。保存位置默认是文档所在的文件夹（SSH 项目为“文档”文件夹）。

语言服务接收 Host 文件 URI。语言服务返回的 URI 写法不同时（例如编码后的盘符冒号或 Windows 上不同的大小写），编辑器仍将其对应到同一文件，包括 Windows 盘符根和 UNC 共享。

恢复存储按工作区保留未保存缓冲区、已开标签及面板尺寸。外部修改会刷新未编辑的缓冲区；已编辑的缓冲区保留文本并提供比较。版本冲突会阻止保存，直到用户处理已显示的差异。运行与调试先保存当前工作区的全部修改，任一保存失败就停止启动。

持续的语言服务分析尚未保存的文档：Python 使用 ty，JavaScript/TypeScript 使用 TypeScript 7 原生编译器（`tsc --lsp`），C/C++ 使用 clangd。补全、悬停提示、签名帮助、诊断、转到定义（F12）、查找引用（Shift+F12）和重命名（F2）都来自这些语言服务；重命名也会修改未打开的文件，这些文件随后以未保存标签页显示。格式化：Python 使用随包 Ruff，JavaScript/TypeScript 使用 TypeScript 自带的格式化，C/C++ 使用已准备的 clang-format。Python 解释器选择与 CMake 编译数据库也用于配置编辑器语言服务。选中代码通过普通用户消息发送，路径、范围和文本一起进入会话记录。

运行按钮按当前文件后缀对应的语言运行该文件。旁边的菜单可为该文件改选其他语言（工作区会记住），或固定运行另一个入口程序的已保存配置；保存当前文件的配置不会将其固定。运行配置按工作区保留入口、参数、解释器或编译器、工作目录及 CMake 选项。Python 支持文件、模块和已有虚拟环境；JavaScript、TypeScript 使用目标环境中已安装的 Node.js（Rainy 不附带）；PHP 支持直接运行脚本；C/C++ 支持单文件及 CMake 构建，失败时停止启动。debugpy、js-debug、Windows CodeLLDB 与 Linux GDB DAP 调试由工作区启动的程序；界面提供断点、单步、调用栈、变量、监视和停止。不提供外部进程附加或 PHP 调试。

运行环境检测检查项目虚拟环境、Conda 注册记录、常见 Python 目录、PATH 和已导入组件，不向这些已有环境安装软件包。所选解释器通过每个进程的环境配置项目工具、终端、运行及语言服务。可执行文件就绪和库能力分别显示：能运行 Python 不代表具备 PyTorch 或 CUDA。另一执行平台的解释器会被拒绝。“设置 → 工具”为 Windows 原生目标下载 PHP 8.5 及 json、openssl、mbstring、pdo_sqlite、curl、zip 扩展。下载前，在 Windows 原生目标运行 PHP 文件会提示下载位置；也可在运行配置中选择已安装的 `php.exe`。已安装的环境组件或项目选定的 PHP 优先。WSL 和 SSH 目标使用该 Linux 系统中安装的 PHP。

离线组件提供隔离的 Python 3.12、Node 24、Windows PHP、原生 C/C++ 工具，以及独立 CPU 或 CUDA 科学计算环境。科学组件包含 NumPy、SciPy、pandas、scikit-learn、图像处理、Jupyter 和常用深度学习库，并配套 PyTorch 2.11、torchvision 0.26 与 torchaudio 2.11。导入先核对发行目录、归档及逐文件清单，再选择按摘要存放的代际。已有用户环境和全局 PATH 保持不变。CUDA 需要兼容的 NVIDIA 驱动。Ubuntu 26.04 amd64 开发工具向导在点击安装时下载经过校验的 C/C++、GDB、CMake、clangd 和 PHP 软件包（约 165 MB，即发行资源中的 `linux-dev-packages` 组件），安装后删除下载的文件；安装时禁用下载。

桌面应用允许已认证 Host 同源的页面复制文本。历史对话中的工具调用按工具类型显示为终端、读取、差异或通用卡片。

## Strata 本地推理

Strata（[Niko1221/Strata](https://github.com/Niko1221/Strata)，MIT 许可）在“设置 → 工具 → Strata 本地大模型”中按需下载，Rainy 不附带它。点击“下载”后，Rainy 读取 Strata 最新发行版的安装清单，下载其中的 Strata Terminal，按清单的 SHA-256 和 GitHub 给出的摘要校验，再用 Strata 签名的更新源确认，然后由 `strata update` 为这台电脑的显卡安装推理引擎。之后启动约 45 秒时和每 6 小时检查一次更新源，没有模型运行时自动更新（可关闭），也可手动“检查更新”。

模型列表来自 Strata 自己的目录（与 Strata 应用相同的管理服务）：每个模型的每个尺寸都标出下载大小、需要的内存和在这台电脑上“放得下 / 会变慢 / 放不下”，并显示 Strata 按这台电脑的内存和显存推荐的尺寸。下载显示进度，可以取消，下次继续；来源可选 Hugging Face 或 ModelScope；默认放在空间最大的非系统盘的 `Strata-data` 文件夹，也可另选。下载完成的尺寸可“启动”和“删除”。

启动通过 `strata launch` 加载模型，上下文长度默认由 Strata 按模型和这台电脑决定，也可固定；端口默认 8080。“连接并设为默认模型”先让当前 Host 验证实际已加载的模型和上下文，再保存本地端点。只能停止 Rainy 自己启动的服务；别处启动的 Strata 服务单独标识。即使项目 Host 使用 WSL，Strata 仍在 Windows 运行；若 WSL NAT 无法访问 Windows loopback，请为 Strata 选择 Windows 执行环境。SSH 服务器上的 Host 无法访问这台电脑上的 Strata。

Strata 的所有文件都在 `%APPDATA%\RainyAgent\tools\strata`（模型除外），每个 Strata 进程都使用这里的文件夹和一个可写、纯英文路径的临时目录，不继承凭据类环境变量和外部 Python 设置，并随 Rainy 退出一起结束。“卸载”删除这个文件夹，并可选择同时删除下载的模型。4.1–4.2 下载的旧 Strata 组件（`modules\strata`）和缓存可在卡片中一键删除。

本版用真实的 RTX 5090 笔记本显卡验证了下载、校验、引擎安装、模型下载、启动、连接对话和停止；其他显卡和 AMD 显卡尚未实测。[验收记录](validation.md)记录具体被测产物和剩余项目。

## 模型体验

每次请求发送前都会估算大小：系统提示、工具定义和消息。如果该对话最近 5 次请求中有服务商报告的输入 token 比估算多，之后的估算会按这个比例再加 10% 放大；更早的偏差不再计入。输入框旁的上下文占用显示该估算，或上一请求由服务商返回的实际用量。估算达到压缩阈值时，较早的一段对话会被摘要替换；这段范围不包含最新的用户请求，也不会拆开工具调用和它的结果。摘要由当前对话的模型撰写。上一请求的提示缓存仍有效时（该请求在 54 分钟内发出，且模型和推理档位相同），摘要请求原样重复该请求，只在末尾加一条指令，因此大部分输入按缓存读取计价；缓存已过期，或模型调用了工具而没有直接回答时，改为单独请求只摘要那一段。展开对话里的压缩记录可以看到用了哪种请求，以及输入、缓存和输出 token 数。摘要会逐字保留仍然有效的用户指令和约束，并记录已验证的进展、准确路径、错误、未完成的工作和下一步；文件、工具或网页中出现的指令只作为数据记录，不会变成任务。模型看到的摘要是助手写的检查点，而不是用户的新请求。上下文溢出错误会先压缩再重试一次；`/compact` 按需压缩。因临时原因失败的请求（服务商过载或限流、连接中断、模型长时间没有返回）会自动重试，最多三次，分别等待约 5、10、20 秒或服务商要求的时间；对话中显示倒计时和“立即重试”，“停止”结束等待。被拒绝的请求（密钥错误、额度用尽、请求无效）不会自动重试。自动重试用完后，或任何请求失败、停止后，点错误处的“重试”即可重新请求模型，不必重发消息。已经恢复的失败缩成一行小字，重试成功的回合不会堆满红框。摘要失败时历史保持不变。明确设置的输出上限（包括 DeepSeek 预设的最大值）优先于默认值。

发往同一端点来源的请求按到达顺序排队。本机回环服务（Base URL 主机为 localhost、`*.localhost`、127.0.0.1 或 [::1]）一次只运行一个请求，其他端点最多并行四个，因此并行的对话和后台请求不必等待彼此的完整输出流。五分钟没有任何输出的流会被中止，单个请求最长运行 30 分钟。

“设置 → 模型 → 网络代理”决定模型请求如何连到服务：“跟随系统”（默认）、“不使用代理”，或“手动设置”HTTP 代理地址（如 `127.0.0.1:7890`，可带 `用户名:密码@`；不支持 SOCKS 代理，已保存的密码显示为 `***`）。跟随系统时，Windows Host 会针对每个服务询问 Windows 使用哪个代理，因此代理设置、“不使用代理的地址”列表和 PAC 脚本都会生效，系统设置变化后 30 秒内生效。在 WSL 中，“跟随系统”使用 WSL 传给 Host 的 `HTTPS_PROXY`、`HTTP_PROXY` 和 `NO_PROXY` 变量，不读取 `~/.bashrc` 等 shell 配置文件；需要代理时请选“手动设置”。“测试连接”在保存前用所选方式访问当前模型的 Base URL。模型发现和 HTTP 方式的 MCP 服务器使用同一代理，修改设置后连接失败的 MCP 服务器会自动重连。本机、局域网、`.local` 和不带点的主机名（如 `gpu-box`）始终直连，AI 运行的命令和终端不走代理。

“设置 → 模型 → 全局提示词”保存的指令（最多 4,000 个字符）会进入所有对话的系统提示，包括已打开的对话。压缩摘要、项目记忆和连接检查使用各自的提示词；留空则不添加内容。

模型设置保存在所选 Host 的 `settings.json`。API 密钥保存在 `.credentials.sealed.json`（权限 0600），用一把由 Windows 数据保护（DPAPI）为当前 Windows 账户保管的钥匙加密；同名环境变量优先。旧版本保存的密钥会在首次启动时加密；如果 Windows 再也无法打开这把钥匙（例如管理员重置了账户密码），需要重新填写 API 密钥。新的 API 模型默认使用 OpenAI Responses，本地模型默认使用 Chat Completions，均可按服务修改。模型列表先显示已保存的配置（由预设保存的配置沿用预设名称），再显示尚未保存的预设；点击“载入”把预设填入表单。DeepSeek 预设使用 1,000,000 上下文 tokens。每个模型的“接受图片输入”开关决定能否给它发送图片、智能体能否截图查看网页：Claude 模型默认接受，关闭后不接受；其他模型开启后才接受，DeepSeek 预设默认开启。服务不支持图片时请求会失败。两个 Claude 预设共用 Anthropic 密钥，只提供模型支持的推理档位，并将提示词缓存保留一小时。发现模型只需要供应商、Base URL、协议和可选密钥，不保存任何内容；保存和单独的流式/工具调用检查需要完整配置。Rainy 不会静默替换为其他模型。首次启动时会一次性导入 1.x profile 中的模型、密钥和全局提示词；1.x 的对话不导入。

Skills 是 `<项目>/.rainy/skills` 和 `~/.rainy-agent/skills` 下包含 `SKILL.md` 的文件夹。系统提示中只放它们的名称和描述（合计最多 4,096 tokens），模型需要时再读取对应文件。MCP 服务在“设置 → Skills 与 MCP”中统一配置，通过 stdio（命令、参数、环境变量）或 HTTP（URL 和 `Authorization` 等请求头）服务所有对话；不支持 Streamable HTTP 的服务器自动改用较早的 HTTP+SSE 方式连接。**从 JSON 导入** 可以读取其他应用（Claude Desktop、Claude Code、Cursor、VS Code、Windsurf、Cline、Zed、Gemini CLI、opencode、Continue、Cherry Studio 等）的 MCP 配置或服务器说明页里的 JSON 片段，粘贴或选择文件都行；导入前逐个列出每个服务器会运行什么（隐藏令牌等敏感值；写在参数里的脚本完整显示并特别提醒），并提示占位符和 Rainy 不使用的字段；与已有服务器完全相同的不再重复添加，只添加勾选的服务器，不覆盖已有的；在新服务器的表单里粘贴 MCP JSON 也会转到这里。环境变量和请求头保存在 `settings.json` 中，不在保存模型密钥的凭据存储中。其工具名为 `mcp__<服务>__<工具>`，调用 60 秒超时，服务说明会加入系统提示。

每个对话可在输入框旁选择权限：“只读”只能读取和搜索文件；“询问”（默认）在项目内直接读写，运行命令、调用 MCP 工具和写入项目外文件前先询问；“完全自动”不再询问。“总是允许”按项目记住简单命令前缀或 MCP 工具，可在“设置 → 安全”中查看。写入和编辑会保存修改前的内容（单个文件不超过 16 MiB），可撤销单次修改或整轮修改，文件之后又被改动过时不会覆盖；命令造成的改动不在撤销范围内。grep 和 glob 工具使用 ripgrep 搜索。读取工具按行分页，默认 2,000 行、每行 2,000 字符、50 KiB；长行截断标记清晰可见，原文件不受影响。写入和编辑要求先读取已存在的文件，并保留其 BOM 与主要换行符。Shell 命令（WSL 和 SSH 目标中为 `bash`，Windows 中为 `pwsh`）默认 60 秒超时，最长 10 分钟。Rainy 不再内置 PowerShell：`pwsh` 优先使用 Windows 基础环境组件、Program Files 或 PATH 中的 PowerShell 7，否则使用 Windows 自带的 Windows PowerShell 5.1；后者不支持 `&&` 和 `||`，系统提示词会注明当前版本；较长输出在回复中保留开头和结尾，完整文本保存在 Host 临时目录的文件中。工作区指令（`AGENTS.md`、`CLAUDE.md` 及其 `.local` 版本，最多 64 KiB）在对话首次请求前加入一次，智能体进入子目录工作时再加入该目录的指令。对话标题取自第一条用户消息。

## 项目记忆

项目记忆使用跨执行端共享的载体项目身份。Windows 与 WSL 共用项目记录，环境事实保留对应执行端范围。SSH Host 的项目和项目记忆保存在服务器上。使用与自动生成分别开关。自动生成会额外产生模型请求费用，新项目默认关闭；已有记忆记录的项目保持原设置。人工编辑必须提供当前显示的修订号，自动更新不能覆盖或移除人工修正的条目。删除保留来源水位与排除摘要，防止旧证据重新生成已删除内容。

完成一轮后，后台等待前台空闲 60 秒，每项目最多每 10 分钟处理一次。它使用所选模型、不带工具，输入最多 4,096 tokens、输出最多 512 tokens，30 秒超时，不自动回退云端。新的前台输入会取消辅助请求。有效条目最多保存 1,024 估算 tokens；新聊天载入最多 512 tokens，且不超过输入预算的 5%，包含召回说明。失败、取消或修订冲突会保留旧记录。召回作为标明为历史资料的上下文条目进入对话，后续请求从对话文件中重放。来源文件变化会使关联的自动事实失效；原始会话日志仍然可用。

## 已知限制与后续工作

发行目标为 Windows x64；签名状态及平台、模型验收以[验收记录](validation.md)中的具体产物为准。其他 WSL2 发行版与模型端点需分别验收。SSH 目标需要装有 `python3` 的 x86_64 Linux 服务器，不支持其他架构和操作系统。MCP 服务不支持 OAuth 登录，也没有扩展市场。资源管理器集成使用经典右键菜单，在 Windows 11 中位于“显示更多选项”里；Markdown 只能导出为 PDF 和 HTML，不能导出为 Word。请求前的 token 数是估算值，每次请求后由服务商返回的实际用量替换。

[发行验收记录](validation.md)负责浏览器性能测量与验收范围。PDF 渲染在页面中进行；单项验收不代表所有输入文档的保真度。
