# Rainy 验收记录

## 3.6.0（2026-10-18）

被测产物为 `Rainy-3.6.0-windows-x64-setup.exe`（182,789,823 字节，SHA-256 `38e58daba59338d6edb5f315c22dcc5fcfeab4a959064a0aff3d0cdba013f4c8`），构建自提交 `ce474ac5d1`；之后的提交只修改本验收记录。Linux 运行环境底座分片为 277,003,078 字节（SHA-256 `03abb06865b4f5775c4068f88dbd29707dfb40c329f5d0a737ae1deea493efae`，内容标识 `064a4746012c745c3601c0d986bd7b70e44e41d18ba99d9b90c60192196f9a0d`），应用层 `linux-app.tar.gz` 6,102,233 字节随安装包附带；PHP 分片与 3.5.1 相同。

### 改动

- **Linux 运行环境分层**：此前每次更新，首次以 WSL 或 SSH 启动都要下载并解包整个约 280 MB 的运行环境，而每个版本实际变化的只有 Host、界面和小资源。现在 `stage-linux.py` 按 `install-runtime.py` 的同一套规则输出两层：底座 `linux-runtime.tar.gz`（Node.js、依赖包、`app/resources/ide`、ripgrep 及依赖链接）和应用层 `linux-app.tar.gz`（`app/dist`、其余 `app/resources`、`runtime.json` 等）。底座以内容摘要（文件内容、可执行位和链接目标，不含时间和属主）标识，解包为 `base-<内容>/`；每个版本解包为 `<应用层摘要>/`，其中的 `node`、`packages`、`node_modules`、`app/node_modules`、`app/bin` 和 `app/resources/ide` 是指向底座的相对链接。底座未变的更新只解包应用层，不下载。第一次升级到分层版本时，内容相同的旧版整包运行环境会以硬链接复用为底座。清理时保留本版本、它的底座和仍有进程使用的运行环境及其底座。SSH 服务器在标准输入中先收到应用层，底座由服务器自行下载，或在下载失败时跟在应用层后面上传。下载失败对话框的说明随之改为“底座有变化，需要联网下载一次”。
- **移除交互式回答**：按用户决定回退 3.5.0/3.5.1 的 `show_widget`、沙箱框架及其开放路由、随附的 Chart.js、d3、Three.js、Idiomorph 和相关设置与文档；3.5.0 的屏幕与缩放适配保留。

### 检查

- **从 3.5.1 升级（WSL，临时 HOME）**：用 3.5.1 的安装脚本解包 3.5.1 的整包运行环境（约 6.1 秒），再用 3.6.0 的安装脚本只提供应用层、不提供底座：0.84 秒完成，底座由旧环境硬链接得到，Host 0.26 秒就绪，启动页 HTTP 200；清理删除旧的整包目录，剩下底座和本版本共 532 MB，Host 仍正常启动。全新 HOME 从底座分片安装约 5.9 秒，Host 正常。用 `release/win-unpacked/resources` 中打包的安装脚本、应用层和元数据重复安装，没有底座时请求下载、有底座时安装成功。
- **SSH（WSL 中临时 sshd，HOME 为临时目录）**：全新服务器上服务器自行从 `v3.6.0-resources` 下载底座、应用层经 SSH 标准输入送达，136 秒后工作台就绪，智能体在服务器上运行脚本并读到结果，页面错误为零。服务器先装 3.5.1 整包运行环境、再禁止服务器下载启动 3.6.0：运行环境步骤 1.41 秒（复用，无下载、无上传），整个启动 6.4 秒，智能体正常，页面错误为零。
- **测试**：本机 Vitest 101 个文件 753 项通过（10 项按平台跳过），两套类型检查通过，脚本测试 35 项通过（4 项 Linux 专用测试在 WSL 中通过：两层安装与底座复用、从整包运行环境以硬链接复用、清理保留正在使用的运行环境及其底座、SSH 的上传与分片下载）。Ubuntu 24.04 与 Windows 2022 CI 通过（[运行记录](https://github.com/RainyMarks/Rainy/actions/runs/39105518483)）。
- **安装包内容**：7-Zip 解开后 9,037 个文件与 `release/win-unpacked` 逐一一致（比 3.5.1 少交互式回答的文件，多应用层压缩包）。
- **试运行**：用临时用户数据启动，版本为 3.6.0，页面错误为零，关闭窗口后进程全部退出。屏幕尺寸抽查（2560×1600 @225%、1280×800 @150%、3840×2160 @150%）没有超出或重叠。

### 验收范围

没有在用户自己的 WSL 发行版上实测升级（规则是不改动用户真实的 `~/.rainy-agent`），升级路径在临时 HOME 和临时 sshd 中验证；底座内容与 3.5.1 相同这一点只对本次构建成立，今后依赖或 Node.js 升级时仍会下载一次新底座。旧版整包运行环境在 SSH 服务器上不会被自动清理（与此前相同）。没有测试从 3.5.1 自动更新到 3.6.0 的安装程序本身。

## 3.5.0（2026-10-17）

被测产物为 `Rainy-3.5.0-windows-x64-setup.exe`（177,086,611 字节，SHA-256 `c336425a57f68bb83d698538fb02d2695503bfa7219634899e0e091a969e189c`），构建自提交 `6ff12993f2`；之后的提交只修改本验收记录。Linux 运行环境分片为 283,603,481 字节（SHA-256 `7b944381efebc28b7aeccaece0bc1f4dd70b36e0ede9e43807846b94ee8c1917`），WSL 和 SSH 共用；PHP 分片与 3.4.0 相同。

### 改动

- **交互式回答**：新工具 `show_widget`，思路来自 CopilotKit 的 Open Intelligent UI（MIT）。模型依次写 title、height、css、html、script；页面从流式参数中渲染预览（未写完的标签、脚本和样式先去掉，用 Idiomorph 平滑更新），参数写完后执行脚本。界面在 Host 的开放路由 `/rainy/widget/frame` 中运行：沙箱框架没有会话 Cookie，所以这个路由和库文件不校验 Cookie，但仍校验 Host 头；CSP 为 `sandbox allow-scripts`，`connect-src 'none'`，图片只允许 data:/blob:，脚本、样式和字体只来自 `/rainy/widget/`。随附 Chart.js 4.5.1、d3 7.9.0、Three.js 0.186.1（含 OrbitControls）、Idiomorph 0.8.0 和两种界面字体（`scripts/prepare-widget-libs.mjs` 从固定版本的依赖生成）。界面跟随明暗主题和配色；`rainy.sendPrompt` 只在用户刚点击过界面时代为发送消息（每 2 秒最多一条），`rainy.openLink` 只打开 http(s) 链接；脚本出错会显示在界面下方并可“让 AI 修复”。折叠工作步骤时交互式回答保持显示。工具属于只读类，不需要批准；**设置 → 通用设置 → 交互式回答** 可关闭（偏好 `widgets`，默认开）。
- **屏幕与缩放适配**：顶部栏的右侧留白把 Windows 标题按钮的宽度算了两次（样式表 146 px 加预加载脚本测得的宽度），而且菜单列可以缩到 0，所以 225% 缩放下搜索框盖住了“文件、编辑、视图”。现在只由预加载脚本留出按钮宽度，菜单和右侧按钮保持完整宽度，搜索框在空间不够时收窄，最窄时只显示文件夹图标。窗口最小尺寸不再固定为 950×650，显示器工作区更小时以工作区为准；系统缩放或分辨率改变、显示器增减、窗口移到另一显示器后，放不下的窗口会被移回并缩小到工作区内。未拖动过的 AI 窗格宽度为窗口的 28%（340–600 px），旧项目保存的默认 400 也按未拖动处理。

### 改动

- **Markdown 所见即所得**：Markdown 标签默认用 Milkdown Crepe 7.22.3 编辑（新视图 `rich`，状态校验同步更新），保留源码、预览和分栏。修改写入同一缓冲区；写回时按行三方合并（`markdown-merge.ts`：载入时的文件、编辑器对它的序列化、编辑后的序列化），未改动的行逐字保留文件原文；表格不对齐列宽，分隔行写成 `---`。关闭会改写图片 alt 文本的 Crepe 图片块，改用行内图片组件，相对路径经 Host 字节路由加载；不提供上传。斜杠菜单、占位文字和代码块界面都有中英文。Milkdown 的变更通知有 200 ms 防抖且在编辑器销毁时丢弃，所以 Ctrl+S、失去焦点和关闭编辑器时都会先把当前内容交给缓冲区。
- **代码编辑器显示错文件**：先以查看器打开的标签（所见即所得 Markdown）切到源码时，代码编辑器仍显示上一个文件；现在编辑器变为可见时会切换到当前文件。
